# 交付协议

在用户工作目录新建项目文件夹，原始资料不覆盖。示例：

```text
项目名-15篇/
  01-文章标题/
    01-封面.jpg
    02-内容.jpg
    标题与文案.txt
    完整文字稿.txt
    资料来源.txt
    原稿附件/             # 仅在有待核原稿且已确认保留时
  ...
  打开预览.html
  封面总览.jpg
  目录.txt
  交付清单.json
项目名-15篇.zip
```

篇数超过99时用三位编号。目录名与当前标题对应；改名同步预览链接、清单、文件映射及ZIP。刷新旧项目时备份，不删除无法确认归属的文件，只清理清单内旧生成页，防止旧高页码混入成品。

内容工作区保存源映射和待核项。不要把实现脚本、OCR乱码或检查拼图混进发布图片目录。

## 验证器输入

项目根目录保存如下格式的 `交付清单.json`，路径全部相对于项目根目录：

```json
{
  "expected_count": 1,
  "size": [1080, 1440],
  "notes": [
    {
      "id": 1,
      "title": "文章标题",
      "folder": "01-文章标题",
      "images": ["01-文章标题/01-封面.jpg", "01-文章标题/02-内容.jpg"],
      "copy": "01-文章标题/标题与文案.txt",
      "transcript": "01-文章标题/完整文字稿.txt",
      "sources": "01-文章标题/资料来源.txt"
    }
  ]
}
```

运行：`python scripts/validate_delivery.py <项目根目录>`。使用当前环境的Python；脚本需要Pillow。若缺少依赖，用可用运行时的图像库完成同等检查，不无故安装整套工具链。

脚本检查编号、文件存在、图片尺寸、重复封面、文案首行标题和过期多余发布图片。它不核实事实，不检查视觉遮挡，也不能证明OCR全文无遗漏。

人工/工具视觉检查：先看总览确认风格与主题差异；逐篇看密集页、最长标题和末页。检查断字、英语拆行、孤立小标题、行间遮挡、表格错位、缺字、页码、Logo状态。通过后重建ZIP并验证解压完整性，打开本地预览交付。
